## How this project is developed

The owner works from a tablet. Almost all development happens in Claude Code
cloud sessions, which have **no Unity Editor and no Unity CLI**. Therefore:

- **GitHub Actions (GameCI) is the compiler and the test runner.**
- **The WebGL build on GitHub Pages is the playtest.**
- **Code is structured so scene and prefab YAML almost never needs editing.**

### Non-negotiable rule

Never claim that code compiles, that tests pass or that a feature works until
the relevant CI run has passed. Nothing in a cloud session can compile Unity
C#. After pushing, check the runs (GitHub MCP tools: `actions_list` →
`list_workflow_runs`, then `list_workflow_jobs` / `get_job_logs`). If you cannot
read them, tell the owner exactly which workflow, job and check to look at.

## Unity version and packages

- Unity **6000.6.0f1** (`ProjectSettings/ProjectVersion.txt`). This is a Unity
  6.6 "Supported/Current" release, not an LTS. Do not change the version
  without the owner's approval. A version change also needs a matching
  `unityci/editor` Docker image to exist (check Docker Hub tags).
- Key packages (`Packages/manifest.json`): URP 17.6.0, Input System 1.20.1,
  Test Framework 1.8.0, uGUI 2.6.0 (TextMeshPro is part of uGUI in Unity 6).
  URP, Test Framework and uGUI are core packages locked to the Editor version.
- `com.coplaydev.unity-mcp` (MCP for Unity) is installed for local Editor
  sessions. It does nothing in cloud sessions or CI.
- Never invent package versions. Verify against the Unity registry
  (`https://packages.unity.com/<package>`) or the 6000.6 manual.

## Folder layout

```
Assets/_Game/
  Scripts/Runtime/    Game.Runtime.asmdef: all game code (namespace Game)
  Scripts/Editor/     Game.Editor.asmdef: Editor-only code, incl. BuildScript.cs
  Tests/EditMode/     Game.Tests.EditMode.asmdef: fast unit tests of plain C#
  Tests/PlayMode/     Game.Tests.PlayMode.asmdef: tests that need the player loop
  Art/ Audio/ Prefabs/ Scenes/ Settings/
.github/workflows/    tests.yml, build.yml
.claude/skills/       Unity's official skills (see UNITY-SKILLS.md)
tools/unity_meta.py   creates .meta files for new assets
```

`Scenes/Main.unity` and `Settings/URP-Mobile*.asset` are generated by
`BuildScript` during CI builds if they are missing. They only exist inside
the CI run unless someone opens the project in an Editor and commits them.

## Rules for working without an Editor

### .meta files
- Every new file **and folder** under `Assets/` needs a `.meta` file with a
  fresh, unique 32-character lowercase hex GUID in Unity's standard format for
  that asset type. Use the helper; do not write them by hand:
  ```
  python3 tools/unity_meta.py Assets/_Game/Scripts/Runtime/NewThing.cs
  python3 tools/unity_meta.py --check    # missing/orphan metas, duplicate GUIDs
  ```
- Never reuse, copy or change an existing GUID. References to scripts and
  assets break silently when a GUID changes.
- When deleting or renaming an asset, delete or rename its `.meta` with it.
- Files and folders starting with `.` (e.g. `.gitkeep`) are ignored by Unity
  and need no `.meta`.
- The helper refuses images, audio, models, fonts, scenes, prefabs, materials
  and shaders, because their importer blocks are type-specific. Prefer creating
  such assets from code (an Editor script run by `BuildScript`); otherwise ask
  the owner to import them in an Editor once.

### Code-first
- Startup goes through `Bootstrap` (`[RuntimeInitializeOnLoadMethod]`). It
  creates the camera, the HUD and the `GameRoot`, so scenes stay nearly empty.
- Objects, UI and configuration are created from code and ScriptableObjects
  (`GameConfig`; put an asset at `Resources/GameConfig.asset` to override the
  defaults).
- Do not hand-edit `.unity` or `.prefab` YAML unless there is no alternative.
  If you do, say so explicitly to the owner in your report.
- Project settings that matter for builds are set in code in
  `BuildScript.cs`, not in `ProjectSettings/*.asset`. Exception: values GameCI
  reads before Unity starts (e.g. `AndroidTargetSdkVersion`, which decides
  which Android SDK platform GameCI installs) must also be in
  `ProjectSettings.asset`.

### Logic and tests
- Gameplay logic lives in plain C# classes (e.g. `ScoreCounter`,
  `SafeAreaMath`) with EditMode tests. MonoBehaviours stay thin: they forward
  Unity callbacks and input to plain classes and render results.
- Every new piece of logic gets EditMode tests. Use PlayMode tests only for
  what needs the player loop.

### Mobile defaults
- Input: Input System only (`activeInputHandler: 1`). Use `Pointer.current` /
  `Touchscreen` / EnhancedTouch, never `UnityEngine.Input`. `Pointer` also
  covers the mouse in the WebGL playtest.
- Portrait orientation (set in `BuildScript`).
- All UI goes under a `SafeAreaFitter` so it respects `Screen.safeArea`.
- `Application.targetFrameRate = 60` (from `GameConfig`).
- URP mobile asset: no HDR, no MSAA, render scale 1, short shadow distance,
  no depth/opaque textures, no post-processing (see `BuildScript.EnsureUrp`).
- No per-frame allocations in hot paths: no LINQ, `new`, string building,
  boxing, closures or `GetComponent` in `Update`. Cache references, update UI
  text only when a value changes.

### Unity skills in `.claude/skills/`
These are Unity's official skills. Skills that drive the Unity CLI or a live
Editor (`unity-cli`, `new-unity-project`, Unity Search, anything that opens
Editor windows or runs code in an Editor) cannot run in cloud sessions:
**follow their guidance, not their commands.**

## CI

| Workflow | Trigger | What it does | Where results appear |
|---|---|---|---|
| `tests.yml` | pull requests, pushes to `main`, manual | EditMode and PlayMode tests (`game-ci/unity-test-runner@v4`), Library cached | Checks "editmode test results" / "playmode test results" on the PR or commit; artifacts `test-results-editmode` / `-playmode` |
| `build.yml` | pushes to `main`, manual | WebGL and Android builds through `BuildScript` (`game-ci/unity-builder@v6`), APK upload, WebGL deploy to GitHub Pages | Artifact `MyGame-android-apk`; Pages URL on the `deploy` job and under Settings → Pages |

- Build entry points: `Game.Editor.BuildScript.BuildWebGL` and
  `Game.Editor.BuildScript.BuildAndroid`. They exit with code 1 on failure.
- A compile error shows up as a failed test job: open the job log and search
  for `error CS`.
- Secrets: `UNITY_LICENSE`, `UNITY_EMAIL`, `UNITY_PASSWORD`. Never create,
  request or print credentials; the owner manages them.
- Newer pushes cancel older runs of the same workflow on the same ref.
- WebGL is built uncompressed because GitHub Pages cannot send the
  `Content-Encoding` headers compressed Unity builds need.

## Placeholders to resolve before release
- Android identifier `com.dor.mygame` in `BuildScript.cs` is a placeholder.
  It cannot change after the app is published on Google Play.
- Android target API level 36 (Google Play requirement for new apps and
  updates from 31 Aug 2026). Re-check https://developer.android.com/google/play/requirements/target-sdk
  each year and update both `BuildScript.cs` and `ProjectSettings.asset`.
- The APK is unsigned for release (debug keystore). Play Store uploads need an
  `.aab` and an upload keystore, which the owner must supply as secrets.
