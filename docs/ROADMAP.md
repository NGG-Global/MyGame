# Open Skies: roadmap

Milestones are ordered; each ends with green CI and a playable WebGL build.
Scope inside a milestone can move; anything not listed is out of scope until
added here.

## M0: Foundation

- [x] Layered assemblies: FlightState, Simulation, Input, Camera, UI, Gameplay, Editor, Tests
- [x] First flight model (replaced in M1)
- [x] Telemetry snapshot in pilot units
- [x] Keyboard and gamepad controls with a throttle lever
- [x] Chase and cockpit cameras; switching does not interrupt control
- [x] Minimal HUD: camera button, temporary developer telemetry line
- [x] `FlightPrototype` scene generated by an Editor command
- [x] Landscape Android and WebGL build settings in code
- [ ] CI green (needs Unity licence secrets) and first WebGL playtest on Pages
- [ ] Owner: open the project once in Unity 6000.6, run
      **Open Skies > Rebuild Flight Prototype Scene**, commit the generated scene and materials

## M1: First playable flight

- [x] Rigidbody aircraft: lift with stall, parasitic and induced drag, thrust
      with engine lag, control and damping moments, raycast landing gear with
      brakes and nosewheel steering (`docs/FLIGHT_MODEL.md`)
- [x] `AircraftConfiguration` ScriptableObject with prototype tuning values
- [x] Keyboard: pitch, roll, rudder, throttle, brakes, reset; device-independent `FlightControls`
- [x] `AircraftTelemetry` and development overlay; force gizmos
- [x] `IFlightAssist` extension point (pass-through only)
- [x] EditMode tests for aerodynamics, engine, atmosphere, gear; PlayMode tests for rest, acceleration, reset
- [ ] CI green
- [ ] Owner: manual flight test in the Editor (take-off, circuit, stall and recovery, landing)
- [ ] First tuning pass from the manual test

## M2: Touch flight controls

- [x] `FlightInputRouter` merging keyboard/gamepad and touch providers
- [x] Floating joystick (pitch/roll), throttle slider, hold-to-brake (ground only)
- [x] Pointer ownership with revocation on focus loss, hiding and lost releases
- [x] Dead zone, sensitivity, response curve, smoothing, opacity settings
- [x] Touch diagnostics overlay; development-build option in CI
- [x] EditMode and PlayMode tests with synthetic pointer events
- [ ] CI green
- [ ] Owner: Android device checklist in `docs/TOUCH_CONTROLS.md` (phone and tablet)
- [ ] Decide touch rudder / nosewheel steering (rudder strip, auto-coordination, or roll-to-steer on ground)

## M2c: Integration and Android prototype (current)

- [x] Integration audit; fixes (Editor build menu, RESET for touch, cockpit eye
      point, mobile frame pacing, disclosure policy in one place)
- [x] Tests for camera states, HUD session buttons, telemetry, touch liveness, disclosure policy
- [x] `docs/PROTOTYPE_TEST_PLAN.md`
- [ ] CI green
- [ ] Owner: first Android device test (development build)

## M3a: Contextual HUD foundation

- [x] `OpenSkies.Awareness` layer: flight phase estimator (ten phases, confidence,
      hysteresis, confirmation and minimum durations, touch-and-go, go-around,
      rejected take-off), runway geometry, warning monitor (stall, sink rate,
      overspeed), disclosure controller with Cinematic / Smart / Detailed profiles
- [x] Contextual HUD: flight data strip, approach guide (PAPI-style lights,
      centreline cue), navigation guide, warning banners, action rail with SYSTEMS,
      HUD profile button; 0.2 s fades, reduced motion (Android system setting)
- [x] Parking brake (input provider); height above ground in telemetry
- [x] Development inspector (phase, confidence, profile, visible elements and
      actions with reasons, warnings, transition log)
- [x] EditMode tests with scripted telemetry; PlayMode layout and session tests
- [ ] CI green
- [ ] Owner: Editor run with the inspector open (full circuit, touch-and-go,
      go-around, rejected take-off); tune `FlightAwarenessConfiguration`
- [ ] Owner: phone test of legibility, banner placement and the action rail reach
- [ ] Decide: warning sounds; motion option in a settings menu

## M4a: Interactive cockpit, first version

- [x] `AircraftSystems`: one authoritative state for flaps, parking brake,
      lights and ignition, changed only through a shared gate (policy, confirmation)
- [x] Flaps and simplified ignition in the flight model; ENGINE OFF caution
- [x] Placeholder cockpit: six instruments (airspeed with arcs from the flight
      model, attitude, altimeter, heading, vertical speed, GPS map), switch row,
      flap selector, exterior lights
- [x] `CockpitInteractionManager`: taps, look, pinch, double tap; shared pointer
      ownership; generous picking
- [x] Focus panel: enlarged instruments and touch-friendly system selectors
- [x] Cockpit camera: drag-to-look with limits, smooth recentring, adjustable and
      remembered field of view
- [x] EditMode and PlayMode tests (`docs/COCKPIT.md`)
- [x] Selection frame on the cockpit item a panel refers to; LOOK FWD in the top
      bar while the view is turned away
- [x] Compiled outside Unity against the 6000.6.0f1 managed assemblies and package
      sources (Editor and Android player); EditMode tests that need no native engine
      run with Unity's Mono (`docs/COCKPIT.md`, Verification status). Not a substitute for CI.
- [ ] Owner: fix the Unity licence secrets (CI stops at activation: invalid
      credential, account blocked after repeated failures)
- [ ] CI green
- [ ] Owner: device checklist in `docs/COCKPIT.md`; tune flap values in a flight test
- [ ] Modelled cockpit art (list in `docs/COCKPIT.md`)

## M2b: Flight model refinement

- Elevator trim; propeller effects (torque, P-factor, slipstream). Flaps are in
  (M4a); validate their values in flight tests.
- Ground effect; wind
- Regression tests: take-off distance, stall speed, climb rate within
  design tolerances (PlayMode)

## M3: Assistance and contextual UI (layer 1)

- Optional assistance (auto coordination, attitude hold, stall protection)
- Contextual elements: trim once modelled (flaps, the landing cue and phase-based
  disclosure are done in M3a/M4a)

## M4: Cockpit (layer 2), remaining

- Modelled cockpit interior with core instruments (airspeed, attitude,
  altimeter, turn coordinator, heading, vertical speed)
- Touch interaction with cockpit controls; HUD hides information the
  instruments show

## M5: Regional airport and coastline

- Fictional airport (runway, taxiways, apron, buildings) and coastline
- Terrain and water within the mobile budget; level-of-detail plan

## M6: Performance and device validation

- Device tiers: 30 FPS baseline, 60 FPS opt-in; graphics settings menu
- Profiling on reference Android devices; allocation-free flight loop

## Later

Tutorials, challenges, systems layer (engine, electrical, fuel, avionics),
weather, time of day.
